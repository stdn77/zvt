**Версія документа:** 1.0
**Дата:** 2026-01-16
**PWA версія:** 1.0.56
**Android версія:** 1.02.12

## 1. ЗАГАЛЬНИЙ ОПИС СИСТЕМИ

### 1.1 Призначення
ZVIT — система оперативного моніторингу стану членів команди/групи з можливістю збору регулярних та термінових звітів. Призначена для координаторів та учасників груп, яким необхідно швидко відстежувати статус членів команди.

### 1.2 Цільова аудиторія
- Координатори волонтерських груп
- Керівники команд
- Організатори заходів
- Будь-які групи, що потребують регулярної звітності

### 1.3 Платформи
| Платформа | Технологія | Мінімальні вимоги |
|-----------|------------|-------------------|
| **PWA** | JavaScript + Service Worker | Сучасний браузер (Chrome, Safari, Firefox) |
| **Android** | Java + Android SDK | Android 7.0+ (API 24) |
| **Backend** | Java Spring Boot | - |
| **База даних** | MySQL | - |

## 2. ФУНКЦІОНАЛЬНІ ВИМОГИ

### 2.1 Модуль автентифікації

#### 2.1.1 Реєстрація нового користувача
| Параметр | Опис |
|----------|------|
| **Вхідні дані** | Номер телефону, ім'я, пароль, email (опціонально) |
| **Верифікація** | SMS OTP через Firebase Phone Auth |
| **Валідація пароля** | Мінімум 6 символів |
| **Результат** | Створення акаунту, автоматичний вхід |

**Потік:**
1. Введення номера телефону
2. Отримання SMS з 6-значним кодом
3. Введення OTP коду
4. Заповнення форми реєстрації (ім'я, пароль)
5. Створення акаунту

#### 2.1.2 Вхід в систему
| Параметр | Опис |
|----------|------|
| **Вхідні дані** | Номер телефону (верифікований), пароль |
| **Опція** | "Запам'ятати мене" для автологіну |
| **Результат** | JWT токен, збереження в localStorage/SecurePreferences |

#### 2.1.3 Скидання пароля
| Параметр | Опис |
|----------|------|
| **Вхідні дані** | Номер телефону (зареєстрований) |
| **Верифікація** | SMS OTP |
| **Результат** | Встановлення нового пароля |

**Потік:**
1. Натискання "Забули пароль?"
2. Введення номера телефону
3. Отримання та введення OTP
4. Введення нового пароля (двічі)
5. Підтвердження зміни

#### 2.1.4 Вихід з системи
- Видалення токену
- Очищення локальних даних
- Перехід на екран логіну

---

### 2.2 Модуль профілю користувача

#### 2.2.1 Перегляд профілю
| Поле | Редагування | Примітка |
|------|-------------|----------|
| Ім'я | ✅ Так | Обов'язкове |
| Телефон | ❌ Ні | Тільки перегляд |
| Email | ✅ Так | Опціонально, можна видалити |
| Версія додатку | ❌ Ні | Тільки перегляд |

#### 2.2.2 Редагування імені
- Мінімум 2 символи
- Максимум 50 символів
- Збереження через `PUT /api/v1/user/profile`

#### 2.2.3 Редагування/видалення email
- Валідація формату email
- Можливість повного видалення
- Використовується для відновлення доступу

---

### 2.3 Модуль груп

#### 2.3.1 Створення групи
| Параметр | Обмеження |
|----------|-----------|
| Назва групи | 3-100 символів |
| Максимум учасників | 2-1000 (за замовчуванням 50) |
| Тип звіту | SIMPLE або EXTENDED |

**Результат:**
- Користувач стає адміністратором
- Генерується унікальний код доступу (8 символів)

#### 2.3.2 Приєднання до групи
| Метод | Опис |
|-------|------|
| Код доступу | Введення 8-символьного коду |
| QR-код | Сканування QR з кодом доступу |

**Статуси приєднання:**
- `PENDING` - очікує схвалення адміна
- `APPROVED` - схвалено, повноправний учасник
- `REJECTED` - відхилено

#### 2.3.3 Код доступу групи
| Дія | Доступ |
|-----|--------|
| Перегляд | Адмін, Модератор |
| Копіювання | Адмін, Модератор |
| Поділитися | Адмін, Модератор |
| Оновити (регенерувати) | Тільки Адмін |

#### 2.3.4 Вихід з групи
- Підтвердження дії
- Видалення з списку учасників
- Видалення історії звітів (опціонально)

#### 2.3.5 Видалення групи
- Тільки адміністратор
- Підтвердження дії
- Видалення всіх учасників та звітів

### 2.4 Модуль управління учасниками

#### 2.4.1 Ролі в групі
| Роль | Права |
|------|-------|
| **ADMIN** | Повний доступ: налаштування, учасники, видалення групи |
| **MODERATOR** | Перегляд учасників, схвалення заявок, перегляд звітів |
| **MEMBER** | Тільки відправка звітів та перегляд своїх звітів |

#### 2.4.2 Управління заявками
| Дія | Виконавець |
|-----|------------|
| Схвалити | Адмін, Модератор |
| Відхилити | Адмін, Модератор |

#### 2.4.3 Управління учасниками
| Дія | Виконавець |
|-----|------------|
| Змінити роль | Тільки Адмін |
| Видалити учасника | Адмін, Модератор |
| Переглянути звіти | Адмін, Модератор |
| Видалити звіти | Адмін |

#### 2.4.4 Контакт з учасником
| Канал | Реалізація |
|-------|------------|
| Телефон | `tel:` URI |
| Signal | `signal.me` deep link |
| WhatsApp | `wa.me` deep link |

### 2.5 Модуль налаштувань групи

#### 2.5.1 Тип звіту
| Тип | Опис |
|-----|------|
| **SIMPLE** | Бінарна відповідь (ОК/НЕ ОК) + коментар |
| **EXTENDED** | 5 текстових полів + коментар |

#### 2.5.2 Слова звіту (для SIMPLE)
| Параметр | Обмеження |
|----------|-----------|
| Позитивна відповідь | До 20 символів |
| Негативна відповідь | До 20 символів |

**Пресети:**
- ОК / НЕ ОК (за замовчуванням)
- ТАК / НІ
- ДОБРЕ / ПОГАНО
- ГАРАЗД / ПРОБЛЕМА
- + / -

#### 2.5.3 Розклад звітів
| Режим | Налаштування |
|-------|--------------|
| **Фіксований час** | До 5 часових точок на день (HH:MM) |
| **Інтервал** | Період від 5 хв до 24 год, час початку |

#### 2.5.4 Назви полів (для EXTENDED)
- 5 кастомних назв полів
- За замовчуванням: "Поле 1" ... "Поле 5"

---

### 2.6 Модуль звітів

#### 2.6.1 Простий звіт (SIMPLE)
| Поле | Обов'язкове |
|------|-------------|
| Відповідь (ОК/НЕ ОК) | ✅ Так |
| Коментар | ❌ Ні |

#### 2.6.2 Розширений звіт (EXTENDED)
| Поле | Обов'язкове |
|------|-------------|
| Поле 1-5 | ❌ Ні (хоча б одне рекомендовано) |
| Коментар | ❌ Ні |

**Додаткова функція:**
- Чекбокс "Зберігати попередній звіт"
- Автозаповнення полів при наступному відкритті
- Дані зберігаються локально per group

#### 2.6.3 Терміновий звіт (URGENT)
| Параметр | Опис |
|----------|------|
| Ініціатор | Тільки Адмін |
| Deadline | 30/60/90/120 хвилин (PWA), 5-120 хв (Android) |
| Повідомлення | Опціональний текст від адміна |

**Потік:**
1. Адмін ініціює терміновий запит
2. Всі учасники отримують push-сповіщення
3. Відображається банер з таймером
4. Учасники відправляють звіти
5. Адмін бачить статус в реальному часі
6. Адмін може завершити сесію достроково

#### 2.6.4 Перегляд звітів
| Функція | Доступ |
|---------|--------|
| Мої звіти в групі | Всі учасники |
| Звіти всієї групи | Адмін, Модератор |
| Звіти конкретного учасника | Адмін, Модератор |
| Видалення звітів учасника | Адмін |

#### 2.7.1 Плитки учасників

#### 2.7.2 Кольорова індикація

|-------|----------|
| 🟢 Зелений | Звіт "ОК" відправлено вчасно |

### 2.8 Модуль сповіщень

#### 2.8.1 Push-сповіщення
| Тип | Опис |
|-----|------|
| URGENT_REPORT | Терміновий запит від адміна |
| SETTINGS_UPDATE | Зміна налаштувань групи |
| REMINDER | Нагадування про звіт (Android) |

#### 2.8.2 Налаштування сповіщень
| Параметр | PWA | Android |
|----------|-----|---------|
| Увімк/Вимк | ✅ | ✅ |
| Вибір звуку | ❌ | ✅ |
| Локальні нагадування | ❌ | ✅ |

#### 2.8.3 Локальні нагадування (Android)
- Прив'язка до розкладу групи
- Збереження після перезавантаження
- Потребує дозволу SCHEDULE_EXACT_ALARM

## 4. API ENDPOINTS

### 4.1 Автентифікація
| Метод | Endpoint | Опис |
|-------|----------|------|
| POST | `/pwa/login` | Вхід |
| POST | `/pwa/register` | Реєстрація |
| POST | `/api/v1/auth/reset-password` | Скидання пароля |
| POST | `/api/v1/auth/logout` | Вихід |

### 4.2 Профіль
| Метод | Endpoint | Опис |
|-------|----------|------|
| GET | `/pwa/profile` | Отримати профіль |
| PUT | `/pwa/profile` | Оновити профіль |

### 4.3 Групи
| Метод | Endpoint | Опис |
|-------|----------|------|
| GET | `/pwa/groups` | Список груп |
| POST | `/pwa/groups` | Створити групу |
| GET | `/pwa/groups/{id}` | Деталі групи |

| DELETE | `/pwa/groups/{id}` | Видалити групу |

| DELETE | `/pwa/groups/{id}/leave` | Вийти |

### 4.4 Учасники
